# Probes

Each file here is one probe: a bash script that checks one property of one file or document, exits zero when the property holds and non-zero when the defect it was written to find is present. The header of every probe states the claim it checks, the file it probes, and what a non-zero exit means. Probes run from the repository root with the repository's own toolchain, without network access, and never depend on anything outside the tree.

A probe is a small script written during an investigation, a review or a design, to ground a claim in a run or a measurement instead of a guess; it lives in the session's scratchpad or the review's own record, never in the tree, and is discarded once its finding lands as a gate. This store holds the probes kept before that rule, and empties claim by claim: each claim moves to a gate, a test the suite runs, a step of CI or a pre-commit or pre-push hook, at the earliest stage whose time budget its check fits and into a gate that already checks its family where one does, and a claim about a tool or a toolchain to a gate run when that tool's pin changes. The change that moves a claim shows the gate red on the defect the probe was written for, retires the probe and names the gate. When the store is empty, its runner goes with it.

A probe never writes a tracked file, not even one it restores before it exits: between the write and the restore the file reads as the user's change to a sweep, a hook or a commit running meanwhile, and the store takes no lock. A probe that has to edit a tracked file to make its claim edits a scratch copy of the file, or of the working tree as a detached worktree of `HEAD` with the uncommitted diff applied, and spells every write under its scratch variable, which is what the probe over the store itself reads for. The runner holds the rule whatever path a probe computes: each probe runs in a Landlock sandbox that refuses a write outside its own directory and the caches that lock themselves, and since the sandbox does not govern a file's times or mode, the runner reads every tracked file's mtime, size and mode whenever a probe starts or ends; a change makes the probes running since the last reading suspects, each runs again alone, and the one that moves a file fails whatever it exited.

A probe shares nothing it writes with another probe. It writes beneath a directory of its own made with `mktemp -d`, under `TMPDIR`, and builds what it runs there: a C++ target in a tree of its own made by `tools/private_cpp_tree.sh`, which configures from the sources `cpp/build` fetched and builds with the tree as ccache's base directory, so a fresh tree is served from the cache; a Rust or Go harness where `benchmarks/run_all.sh` is told to build it; an Agda check in a copy of the project and its interfaces. A tree a lane builds, a mutation or coverage tree, it reads as the lane left it, and refuses one too stale for its claim. The one shared thing a probe writes is a cache that locks itself: the tool caches in the home directory and the git directory.

Run them all with `./probes/run_all.sh`, which runs `PROBE_WORKERS` of them at once, 4 unless told otherwise, or run any one of them the same way. The runner prints one line per passing probe, whatever the probe said, in path order whatever order the probes finish in. A failing probe's line carries its exit status and is followed by the last lines of its own output, and the whole output is kept under `tools/ci-output/probes/` in a file the line names, so a probe that crashed reads differently from one that refused its claim. Every line carries the probe's wall time after its path, and the run's times are kept in `timings.tsv` in that directory, one row per probe with its verdict; the directory holds only the latest run's failures and times. Two runs' records are compared with each line's time taken out, since it moves from run to run. The runner exits non-zero when any probe fails. Every probe states its own interpreter in a shebang and carries the exec bit, so none of them depends on the caller's shell being the one it was written for.

Two probes read state the review store keeps outside the tree, under `.git/frev/`: the list of paths a round has touched, and a baseline of what was already untracked when the round opened. The baseline is captured once, at round open and before the round creates anything, with `git ls-files --others --exclude-standard`, and an entry ending in `/` stands for every path beneath it, which is how a corpus a tool fills as it runs is recorded without listing each file. Without it the staging probe cannot tell a file the round forgot to stage from one that was already there, and it says so rather than passing.

A probe is named `<subject>--<property>.sh`, where the subject is the probed file's path with `/` replaced by `_`. A probe that fails after a change is a regression to fix before that change is committed. A probe whose subject was removed on purpose is retired in the same commit that removes the subject, with the reason in the commit message. A probe is never edited to pass.
