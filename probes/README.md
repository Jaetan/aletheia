# Probes

Each file here is one probe: a bash script that checks one property of one file or document, exits zero when the property holds and non-zero when the defect it was written to find is present. The header of every probe states the claim it checks, the file it probes, and what a non-zero exit means. Probes run from the repository root with the repository's own toolchain, without network access, and never depend on anything outside the tree.

Probes are the review's instruments, kept so a later change that breaks what an earlier review proved is caught when the whole store is re-run. A claim a gate can hold moves to that gate, a test the suite runs, a step of CI or a pre-commit or pre-push hook, at the earliest stage whose time budget its check fits and into a lane that already checks the same thing where one does; the change that moves it shows the gate red on the defect the probe was written for, retires the probe, and names the gate. The store keeps what no gate can hold: a dismissed candidate, a property of a tool, a toolchain or the machine rather than of the tree, and a check past every stage's budget or too sensitive to its machine to gate a change.

A probe never writes a tracked file, not even one it restores before it exits: between the write and the restore the file reads as the user's change to a sweep, a hook or a commit running meanwhile, and the store takes no lock. A probe that has to edit a tracked file to make its claim edits a scratch copy of the file, or of the working tree as a detached worktree of `HEAD` with the uncommitted diff applied, and spells every write under its scratch variable, which is what the probe over the store itself reads for; the runner reads every tracked file's mtime, size and mode before and after each probe, and fails the probe that moved one whatever it exited, which is the check a computed path escapes.

A probe that needs a mutation sweep reads a kept one from `tools/mutation_sweep_cache.py` rather than sweeping for itself: `sweep_directory` for the C++ lane, or for a variant of it run in another order of the cases or without `--abort`. The first probe to ask for a sweep of the tree as it stands makes it, and every later one is served it until what the sweep reads, or how it runs, changes.

A probe shares nothing it writes with another probe. It writes beneath a directory of its own made with `mktemp -d`, under `TMPDIR`, and builds what it runs there: a C++ target in a tree of its own made by `tools/private_cpp_tree.sh`, which configures from the sources `cpp/build` fetched and builds with the tree as ccache's base directory, so a fresh tree is served from the cache; a Rust or Go harness where `benchmarks/run_all.sh` is told to build it; an Agda check in a copy of the project and its interfaces. A tree a lane builds, a mutation or coverage tree, it reads as the lane left it, and refuses one too stale for its claim. The one shared thing a probe writes is a cache that locks itself: the tool caches in the home directory, the git directory and the sweep cache.

Run them all with `./probes/run_all.sh`, or any one of them the same way. The runner prints one line per passing probe, whatever the probe said. A failing probe's line carries its exit status and is followed by the last lines of its own output, and the whole output is kept under `tools/ci-output/probes/` in a file the line names, so a probe that crashed reads differently from one that refused its claim. Every line carries the probe's wall time after its path, and the run's times are kept in `timings.tsv` in that directory, one row per probe with its verdict; the directory holds only the latest run's failures and times. Two runs' records are compared with each line's time taken out, since it moves from run to run. The runner exits non-zero when any probe fails. Every probe states its own interpreter in a shebang and carries the exec bit, so none of them depends on the caller's shell being the one it was written for.

Two probes read state the review store keeps outside the tree, under `.git/frev/`: the list of paths a round has touched, and a baseline of what was already untracked when the round opened. The baseline is captured once, at round open and before the round creates anything, with `git ls-files --others --exclude-standard`, and an entry ending in `/` stands for every path beneath it, which is how a corpus a tool fills as it runs is recorded without listing each file. Without it the staging probe cannot tell a file the round forgot to stage from one that was already there, and it says so rather than passing.

A probe is named `<subject>--<property>.sh`, where the subject is the probed file's path with `/` replaced by `_`. A probe that fails after a change is a regression to fix before that change is committed. A probe whose subject was removed on purpose is retired in the same commit that removes the subject, with the reason in the commit message. A probe is never edited to pass.
