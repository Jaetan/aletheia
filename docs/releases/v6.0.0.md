# Aletheia v6.0.0

v6.0.0 is a major release: every binding and the C ABI change. This page lists the changes that can break a v5.0.0 program, script or file, by what you use, then the main additions; the changelog marks the larger ones. The [changelog](https://github.com/Jaetan/aletheia/blob/v6.0.0/CHANGELOG.md) lists the rest.

## Breaking changes

### No error points these out

- Python: a `within`, `for_at_least`, `metric_until` or `metric_release` written in milliseconds runs with a window 1000 times shorter.
- C++: `numerator()` is never negative: `static_cast<double>(r.numerator())` on -1/2 gives 1, not -1; read the sign with `negative()`.
- Rust: `numerator()` is never negative: `r.numerator() as f64` on -1/2 gives 1, not -1; read the sign with `is_negative()`.
- Python YAML checks: `017` is 17, not 15, and `!!float 0.1` is 1/10, not the nearest double.
- Rust: `Rational` is stored in lowest terms, so `new(2, 4)` equals `new(1, 2)` and its numerator is 1.
- Rust: a match on `Error::Protocol(_)` compiles and no longer catches a refused frame build, update or extraction: it is `Error::Core`.

### Every binding

- Time windows are whole microseconds: Go, Rust and C++ `within` take a `TimeBound`, Python's methods `time_us` in place of `time_ms`.
- YAML's `within_ms` is `within_us`; the Excel columns `Time (ms)` and `Within (ms)` are `Time (µs)` and `Within (µs)`.
- Building a predicate, property or check needs the runtime up: call `start_runtime` or open a client first.
- The log events `enrichment.extraction_failed` and `enrichment.property_index_oob` are gone.
- An enrichment whose extraction the kernel refuses fails the frame or the end of stream, where it was logged and went on.
- A decimal past the bound is the typed bound error, in loaders too, where it was a validation error.
- A reply missing a place the kernel writes is refused, a mock's included, where it read as empty or a default.
- A DBC reply writes `extended` on every identifier, `false` too; v5.0.0 wrote only `true`.
- Error message texts changed in every binding and command line: match codes, kinds and fields, never the text.
- Rational parts, multiplex values and value-description keys reach 2^128 - 1, sign apart: Go `Uint128`, C++ `unsigned __int128`, Rust `u128`.
- `start_runtime` starts the runtime alone; a client naming no core count takes the running one; a count outside 1 to the process's CPUs is refused.
- Wire codes `dbc_text_parse_failure` and `dbc_text_trailing_input` become `text_parse_failure` and `text_trailing_input`; `decimal_parse_failed` and `decimal_overflow` give way to the kernel's codes.
- A number a YAML or Excel loader refuses is the kernel's error with location and key; loading any YAML check, integers too, needs the runtime up.
- `frame_injection_failed` is gone: match `frame_value_out_of_range` and `frame_value_not_representable`; an inexact value is refused, not rounded.
- The FFI backend refuses any payload whose length is not the DLC's byte count, as each client does; v5.0.0 checked at most the 64-byte cap.
- The `frame_byte_count` bound kind and its 64-byte constant are removed; the C ABI answers a wrong length `parse_payload_length_mismatch`.
- Six wire codes are removed: `handler_invalid_dlc_code`, `extraction_bit_extraction_failed`, `route_missing_array`, `route_dlc_exceeds_max`, `route_byte_count_mismatch`, `route_byte_array_parse_failed`.

### C ABI

- `aletheia_build_frame_bin` refuses a DLC code from 16 to 255, where it wrote that many bytes.
- An extraction buffer's value entry is 35 bytes (`u16` index, sign byte, two 128-bit parts), where it was 18 with two `i64`.
- A v5.0.0 client has no version check: pointed at the v6.0.0 library it can end the process. Upgrade both together.
- C ABI 4: numerators, denominators, multiplex values and value-description keys reach 2^128 - 1, sign apart; `aletheia.h` requires C23.
- `aletheia_allocated_bytes` is a new entry: it runs a collection and returns the bytes the runtime has allocated.
- `aletheia_parse_decimal` refuses with the kernel's envelope; `decimal_parse_failed`, `decimal_overflow` and the echoed `input` field are gone.
- A binary-output entry always sets the buffer's `err` to the JSON error envelope with its `code`; most v5.0.0 refusals were a bare message.
- Entries take and return values in structures passed by pointer; `aletheia_abi_version()` reports the ABI and loaders refuse another.
- `aletheia_process` and `aletheia_parse_decimal` take a `const struct aletheia_text *` (bytes and count, no NUL), read as UTF-8 whatever the locale.

### DBC text and the kernel

- `min_exceeds_max` is an error, not a warning, for signals, attribute definitions and environment variables: such a DBC is refused.
- A value-description key outside its signal's bits is the new error `value_description_key_out_of_range`, and refuses the load.
- An Intel signal a short frame does not carry is an error (`extraction_signal_past_frame_end`), where it was read as zero.
- A frame is built or updated only where its bytes hold every Intel signal placed; otherwise `frame_signal_past_frame_end`.
- A name no identifier in a `.dbc` text is `parse_invalid_identifier` at its line and column, where it was a parse failure.
- A command text that is not RFC 8259 JSON is refused with `dispatch_invalid_json`; replies are such text, control characters escaped.
- Refused: text outside the DBC character set, a name that is no DBC identifier, an unknown `setProperties` signal; a `.dbc` is read byte for byte.
- JSON extraction refuses a value whose reduced numerator or denominator is past 2^128 - 1, with `extraction_value_exceeds_wire_range`.
- Every list in a DBC has a bound; past it every DBC command, `formatDBCText` included, refuses with `input_bound_exceeded`.
- Rust and C: a JSON command's length counts UTF-8 bytes, so non-ASCII text past 64 MiB of bytes is refused though its characters are fewer.
- `duplicate_message_id`, `duplicate_message_name` and `global_name_collision` are one issue per shared key naming every message, not one per pair.
- An update (`aletheia_update_frame_bin`) refuses two requested signals that share a bit, with `frame_signals_overlap`, as a build does.
- A signal whose declared range reaches past its bits is the issue `range_exceeds_bits`; a load refuses its DBC with `handler_validation_failed`.
- A frame's bad DLC, length or identifier is refused with a typed `parse_*` code, not `ffi_validation_error` or a `frame_byte_count` bound.
- A `.dbc` number past 2^128 - 1 once reduced, or an INT, HEX or ENUM attribute value past 2^63 - 1, is refused at load, its field named.
- A bound refusal's `observed` stops at 2^128 - 1; past it the message names the limit alone.

### Python

- `Backend.build_frame_bin` and `update_frame_bin` take `values`, a tuple of `Fraction`, in place of numerators and denominators.
- A JSON reply that cannot be read raises `ProtocolError`, where `UnicodeDecodeError`, `ValueError` or `RecursionError` escaped.
- YAML checks refuse `0x1F`, `1_000`, `+5`, `1:30` and padded quoted numbers, and malformed YAML raises `ValidationError`, not `yaml.YAMLError`.
- A signal value past the wire's range raises `InputBoundExceededError`; a whitespace-only Excel cell is absent; error texts lose `build_frame failed: `.
- `ALETHEIA_RTS_OPTS` is split on the six ASCII whitespace bytes only, as in the other bindings.
- In a YAML check, a plain number, boolean or date under a text key is its text: `name: 42` names the check, where it was dropped.
- `from aletheia.dsl import UntilFormula`, `ReleaseFormula`, `MetricUntilFormula` or `MetricReleaseFormula` fails: import it from `aletheia.types`.
- `FractionJSONEncoder` writes non-ASCII text as its characters, and `from_decimal` of a lone surrogate raises `ValidationError`.
- Building the package needs setuptools 84.2.1, and its metadata carries a license expression in place of the License classifier.
- An issue's code outside its set is refused; a `ValidationIssue` holds `IssueSeverity` and `IssueCode` members, where it held plain strings.
- The `code` of `AletheiaError`, its subclasses and `ErrorResponse` is an `ErrorCode` where it was a `str`; a member compares equal to its word.
- A null reply from a C entry is an `FFIError` reading `<entry> returned null`, where a text endpoint raised `ProtocolError`.
- `FFIBackend.init`'s `FFIError` reads `aletheia_init returned null`, where it named the call `aletheia_init()`.
- An unknown non-ASCII `ALETHEIA_RTS_OPTS` flag is refused by the runtime on stderr with exit status 1, where Python raised `UnicodeEncodeError`.
- Nothing is printed until the host configures logging; `cache.full` is logged once per fill; log booleans read `true` or `false`.
- `parse_dbc` and `parse_dbc_text` raise `InputBoundExceededError` for a bound; catch it where the returned `ErrorResponse` was read.
- The constant for a DBC text field's bound is named in characters, not bytes: `MAX_STRING_LENGTH_CHARACTERS`.
- `aletheia.asyncio.testing.gated_backend` is gone; in tests hand the async client a `TurnExecutor` as its `run_in_thread`.
- `aletheia.dbc` no longer exports `dbc_and_warnings_from_response`; it stays in `aletheia.dbc._converter`.

### Go

- Comparisons return `(Predicate, error)`, `AlwaysWithin` and `EventuallyWithin` `(Formula, error)`, and the check builders `(CheckResult, error)`.
- `Within` and the last parameter of `DispatchThen` take a `TimeBound`, not milliseconds; `TimeBound.Microseconds` is a `uint64`.
- `Rational` is a sign and two `Uint128` magnitudes, `MultiplexValue` a `Uint128`, and a value entry's value a `SignMagnitude`.
- A comment or attribute target whose `CANID` is unset is refused, where it was read as identifier 0.
- `InputBoundExceededError`'s `Observed` and `Limit` are `Uint128`, not `uint64`, and a command holding invalid UTF-8 is refused.
- Size refusals by `ParseDBC` and the YAML and Excel loaders carry `Code` `input_bound_exceeded`, where it was empty.
- `excel.CreateTemplate` that cannot save returns an `*aletheia.Error` of `ErrValidation`, not the spreadsheet library's error.
- `SendFrames` of no frames is refused on a closed client; a workbook refused for its expanded size reports that size in `Observed`.
- `MaxRationalComponentMagnitude` is past every Go integer type.
- The Go binding needs Go 1.26 or later: the core module, the Excel module and the command line declare `go 1.26.0`.
- An unknown issue code or error code is refused at its place in the reply, where it was kept as read; `IssueUnknown` is removed.
- A property result's type or a stream warning's kind outside its set is refused; `StreamWarning.Kind` is a `WarningKind`, not a `string`.
- The `Code` of `Error`, `InputBoundExceededError`, `ValidationFailedError` and `TextRoundTripFailedError` is an `ErrorCode`, not a `string`.
- `ALETHEIA_RTS_OPTS` is split on the six ASCII whitespace bytes only: a Unicode space such as U+00A0 stays in its flag.
- A null render reads `aletheia_format_rational returned null`, where it read `aletheia_format_rational returned a null pointer`.
- `cache.full` is logged once per fill, and again only once a new stream or new properties empty the cache.
- `Error()` drops its `aletheia <kind> error: ` prefix and returns the message; the kind, code and issues are the error's fields.
- The session handle is `aletheia.State`, an integer newtype, not an `unsafe.Pointer`; change code that calls or wraps a `Backend`.
- The constant for a DBC text field's bound is named in characters, not bytes: `MaxStringLengthCharacters`.
- `DBCAttrTargetMessage`, `DBCAttrTargetSignal`, `DBCAttrTargetNodeMsg` and `DBCAttrTargetNodeSig`: `ID` is a `CANID`, `Extended` is removed.
- `BuildFrameBin` and `UpdateFrameBin` of the backend interface take one slice of `SignalInjection` instead of a signal count and three slices.
- DBC records carry `SignalName` and `NodeName`, not strings; `NewDBCMessage` takes `[]NodeName`; message and signal comment targets carry a `CANID`.
- `DispatchSimple` and `DispatchThen` take an interface, not rationals; `IsSimpleValueCondition` and its three siblings go, `IsSimpleCondition` stays.
- The modules are `go`, `go/excel` and `go/cmd/aletheia` of this repository, the major `/v6` last, not `github.com/aletheia-automotive/aletheia-go`.
- `RegisterDefaultLibPath` is removed; the package `aletheia` searches for no library.

### Rust

- Comparisons, `Formula::always_within`, `eventually_within` and the check builders return a `Result`, and `within` takes a `TimeBound`.
- `Rational::numerator` and `denominator` are `u128`, with the sign in `is_negative`; `Presence::Multiplexed` values are `u128`.
- `StreamWarning.kind` is a `WarningKind`, `ValueDescription.value` a `SignMagnitude`, and `SignalInjection` holds `values`.
- `Error::RtsNotInitialized` carries its `operation`, and `Dbc.unresolved_value_descs` holds `RawValueDescription`s.
- The crate needs Rust 1.88; `Rational::integer` takes an `i128`, and an unsuffixed literal past `i32` in a builder needs a suffix.
- A YAML number spelled `0x1F`, `0o17` or `+5` is refused and a quoted one is read; `rts.cores_mismatch` carries integers.
- An unknown issue code or error code is refused; `IssueCode::Unknown` is removed and `IssueCode::from_wire` returns `Option<IssueCode>`.
- Every error `code` is an `ErrorCode` where it was a `String`, and `IssueCode::as_str` takes `self` by value.
- A null reply from a C entry, a null render included, is `Error::NullResponse { entry }`, no longer a unit, and reads `<entry> returned null`.
- `ALETHEIA_RTS_OPTS` is read as bytes and split on the six ASCII whitespace bytes: a Unicode space or a non-UTF-8 byte stays in its flag.
- `Error::Validation` is a struct variant whose `code` is `Some` for a kernel refusal; a match on `Error::Validation(_)` no longer compiles.
- `Display` drops `validation error: `, `protocol error: `, `core error [<code>]: ` and the issue count; the code and issues are fields.
- `Error::InputBoundExceeded` holds a `Box<BoundRefusal>`: match a tuple variant; `observed` and `limit` are `u128`, `message` and `field` new.
- `Error::NulInString` is removed: a text is passed with its length, and the library refuses a NUL in it with `ffi_validation_error`.

### C++

- Comparisons, `between`, `changed_by`, `stable_within`, `within` and the check builders return `Result`, and `within` takes a `TimeBound`.
- `AletheiaException` is gone; factories and conversions (`create`, `from_decimal`, `Rational::make`, `bytes_to_dlc`) return `Result`.
- `Rational::make` takes a sign and two magnitudes; `MultiplexValue` is 128-bit; a value entry's value is a `SignMagnitude`.
- The shipped C++ source needs libstdc++ 15; libstdc++ 14, which Ubuntu 24.04 ships, has no `vector::append_range`.
- The DBC workbook loader refuses a message id past sixteen bits, where it read the low sixteen, and a stored integer with a plus sign.
- `aletheia-cpp` is always shared: a program built on it, and an installed `aletheia-cli`, load `libaletheia-cpp.so.4` at run time.
- With libstdc++ 15 the headers need `-std=gnu++23`: strict `-std=c++23` does not compile them.
- `Rational`'s two-argument constructor takes constants only, and `Rational` has no ordering: only `==` is left.
- A YAML or Excel load with the runtime down answers kind `Ffi`, where it was `Validation`; `IBackend::close` is `noexcept`.
- `make_mock_backend()` acknowledges text endpoints and answers frames with zeros, where it refused both with kind `State`.
- Loaders, `ltl` builders, `format_formula` and backend factories are `[[nodiscard]]`: a discarded result fails a `-Werror` build.
- Configuring the C++ source also fetches miniz and pugixml; `InputBoundExceededError`'s counts are `unsigned __int128`.
- `make_ffi_backend` refuses an empty path with kind `Validation`, where it was `Ffi`.
- Unknown issue and error codes are refused; removed: `IssueCode::Unknown`, `ErrorCode::Unknown`, `code_raw`; `AletheiaError::code()` is optional.
- A property result's type or a stream warning's kind outside its set is refused; `StreamWarning::kind` is a `WarningKind`, not a `std::string`.
- A null reply from a C text entry is refused with kind `Ffi`, where it was `Protocol`, and reads `<entry> returned null`, as a null render does.
- `issue_code_label` is removed under `libaletheia-cpp`'s `SOVERSION 4`: call `to_string(issue.code)` to render an issue's code.
- Every error is a `Result<T>` and only `std::bad_alloc` is thrown; the `AletheiaClient` constructor is private: use `open` or `create`.
- `libaletheia-cpp` is at `SOVERSION 4`, with a moved client layout: rebuild. `cache.full` is logged once per fill, not per uncached extraction.
- The constant for a DBC text field's bound is named in characters, not bytes: `max_string_length_characters`.
- A check always carries its formula: `CheckResult::formula()` and `to_formula()` return a formula rather than an optional.
- `aletheia-cpp` is a shared library, not a static archive; a consumer that linked the archive by path needs its directory on the run-time search path.
- `libaletheia-ffi.so` is found by one search, `aletheia::find_ffi_library()`; the CLI no longer falls back to `/usr/local/lib`: set `$ALETHEIA_LIB`.
- `Rational::to_double()` is removed; divide `numerator()` by `denominator()`, unsigned magnitudes now, and negate where `negative()` is true.
- Node-valued DBC fields are `NodeName`, not `std::string`; comment and attribute targets carry a `CanId`, not an id and an `extended` flag.
- `DbcDefinition::unresolved_value_descriptions` is renamed `unresolved_value_descs`; the wire is unchanged.
- `IBackend::init()` returns `Result<BackendState>`, the owning state every endpoint takes; `close()` is protected; use `SignalInjection::create`.

### Command lines

- Python, Go and C++: an extra positional, a flag after a bare `--` and a report that cannot be written exit 2.
- Python: an operating-system error or a missing extra exits 2 with one `Error:` line, where it was a traceback and exit 1.
- C++: `--dbc` takes a regular file, not a pipe; the library search takes `../../build` before `build`; warnings go to stderr.
- Go: the library search takes `../../../build` in place of `../../build`; warnings go to stderr, as in the C++ command line.
- Python: `mux-query` on a message that is not multiplexed prints one line, not two; `examples/demo/drive_log.py` writes only with `--update`.
- Go: `mux-query --mux --value` prints the message header with its payload length, a selector line and a name per line, as the other CLIs.
- C++: the `mux-query` header carries the payload length, and the summary prints the signal names its siblings print; wording matches the other CLIs.
- Benchmark `run_all.sh` refuses a flag its mode does not read: throughput `--frames --runs`, latency `--frames --warmup`, scaling `--runs --quick`.

## Main additions

- `aletheia template <file>.xlsx`, in the Python, C++ and Go command lines, writes the blank workbook the Excel loaders read.
- The Go Excel loader and the Go command line, each a module of its own, are tagged with every release; `go install` takes the latter (see the [Go guide](https://github.com/Jaetan/aletheia/blob/v6.0.0/go/README.md)).
- Python's `Predicate` gains `until`, `release`, `metric_until` and `metric_release`; Go's signal builder and Rust's `Predicate` carry every kernel predicate.
- Every binding can start the kernel's runtime alone, with `start_runtime`, so checks load before a client.
- Loading a DBC, from JSON or text, takes time linear in its length.
- `find_package(aletheia-cpp)` gives the whole declared surface of the C++ library, shared by default.
- The release bundle and the packages carry the license text of every library they ship.
